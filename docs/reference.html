A SMALL FIRST STEP

Your first image.

Start your instance, set BYTEDOWN_API_KEY on your backend, and choose a JPG or PNG. Examples use http://127.0.0.1:8080; use your HTTPS instance URL in production. 

curl --fail-with-body \
  -H "Authorization: Bearer $BYTEDOWN_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -F 'file=@photo.jpg' \
  -F 'profile=web' \
  http://127.0.0.1:8080/v1/images
// Node.js 22+ · trusted server code only
import { readFile } from 'node:fs/promises';
import { randomUUID } from 'node:crypto';

const body = new FormData();
body.append('file', new Blob([await readFile('photo.jpg')]), 'photo.jpg');
body.append('profile', 'web');
const submissionKey = randomUUID(); // retain for retries of this submission
const response = await fetch('http://127.0.0.1:8080/v1/images', {
  method: 'POST', body,
  headers: {
    Authorization: `Bearer ${process.env.BYTEDOWN_API_KEY}`,
    'Idempotency-Key': submissionKey,
  },
});
if (!response.ok) throw new Error(await response.text());
console.log(await response.json());
# Python 3 · pip install requests · trusted server only
import os, uuid, requests

submission_key = str(uuid.uuid4())  # retain for ambiguous retries
with open('photo.jpg', 'rb') as image:
    response = requests.post(
        'http://127.0.0.1:8080/v1/images',
        headers={
            'Authorization': 'Bearer ' + os.environ['BYTEDOWN_API_KEY'],
            'Idempotency-Key': submission_key,
        },
        files={'file': ('photo.jpg', image, 'image/jpeg')},
        data={'profile': 'web'}, timeout=150,
    )
response.raise_for_status()
print(response.json())

A successful upload returns HTTP 202 with image_id, job_id, and status_url. Reusing an identical submission’s idempotency key returns the existing IDs. 

# Replace JOB_ID with the job_id returned by your upload.
curl --fail-with-body \
  -H "Authorization: Bearer $BYTEDOWN_API_KEY" \
  http://127.0.0.1:8080/v1/jobs/JOB_ID

# When status is succeeded, retrieve the output manifest.
curl --fail-with-body \
  -H "Authorization: Bearer $BYTEDOWN_API_KEY" \
  http://127.0.0.1:8080/v1/images/IMAGE_ID
Poll about every two seconds, back off after network failures, and stop on succeeded or failed. Upload acceptance is not processing completion.
KEYS STAY BACKSTAGE

Authentication.

Send Authorization: Bearer YOUR_API_KEY on protected requests. Keep the key in your server’s secret configuration. Never put it in a frontend bundle, browser storage, public environment variable, or download URL.

Browser workshop

The built-in interface uses a separate operator password and an HttpOnly, SameSite=Strict session cookie. Sessions last eight hours and reset when the API restarts. Mutations require an exact Origin match and an X-CSRF-Token retrieved from GET /ui/session.

This is a single-operator service. There is no registration or tenant-level access control.

Originals always require authorization. Variants require authorization by default; PUBLIC_VARIANTS=true makes only generated media public. CORS is disabled by default.

POST/v1/imagesSchema ↗

A new beginning for your image.

Send multipart/form-data with exactly one file and an optional profile (default web). File contents are validated in an isolated native child before a job is accepted. Uploading does not synchronously encode outputs.

Field Type Details
file Binary · required One static JPEG or PNG. The extension alone is not trusted.
profile String A configured profile name from capabilities. Defaults to web.
Idempotency-Key Header · optional At most 200 bytes; no surrounding whitespace. Keep the same value when retrying an ambiguous upload.

Identical content and resolved profile with the same key returns the existing submission. A conflicting reuse returns 409. Separate submissions are not automatically deduplicated by content hash.

GET/v1/jobs/{job_id}

Progress without the guesswork.

queued → processing → succeeded / failed

generated and planned count actual outputs; duration_ms measures processing time, not time waiting in the queue. Progress can reset on a worker retry. Partial outputs remain unpublished until the whole job succeeds.

Failed jobs include sanitized error_code and error_message. An identical idempotent upload returns that same failed job; it does not restart processing. To deliberately submit again after correcting a problem, use a new submission key.

GET/v1/images/{image_id}

Meet the alternatives.

The manifest is the source of truth: original dimensions, encoded dimensions, bytes, original_url, and an outputs array with format, width, height, bytes, and URL.

A smaller file is a result, not a promise. Positive size_difference_percent means a reduction; negative means growth. includes_resizing indicates that dimension changes contributed. Different formats are alternatives—do not add their savings together.
GET/v1/images?limit=50&offset=0

List stored images. limit: 1–100; offset: 0–1,000,000. Optional status filters by a job state. Response: images, limit, offset. Offset pagination can shift while images are added or removed.

Ready when you are.

GET/media/{output_id}

Download a completed generated output using its manifest URL.

GET/v1/images/{image_id}/original

Download the untouched original, byte for byte. Its encoded dimensions can differ from orientation-normalized display dimensions. 

# Use an output URL from the manifest; do not construct output IDs.
curl --fail-with-body \
  -H "Authorization: Bearer $BYTEDOWN_API_KEY" \
  http://127.0.0.1:8080/media/OUTPUT_ID \
  --output photo.webp
GET/v1/archive?images=IMAGE_ID,IMAGE_ID

The whole set, neatly packed.

Stream a ZIP of generated outputs from completed images. Originals are excluded; responsive sizes are included. Entries use image-specific folders and output IDs to avoid collisions. The server accepts IDs only, never filesystem paths.

10 unique images160 files maximum512 MiB maximumStored ZIP entries

Incomplete images return 409. Missing outputs return 404. A storage or network failure after streaming begins can leave a truncated archive; retry the download.

DELETE/v1/images/{image_id}

A clean slate.

Deletes the image, job, output references, and idempotency record. Returns 204. Active worker publication is invalidated so a deleted image cannot reappear when processing finishes. Stored files are removed best-effort; the worker reconciles orphaned files.

Deletion is permanent. Already-started downloads may finish, and public caches can retain variants for their advertised 86,400-second lifetime. Clearing an item from the workshop view does not delete it from the server.
GET/v1/capabilities

Your instance sets the limits.

Read resolved profiles, encoder availability, service/pipeline versions, limits, and public_variants. Treat these as authoritative rather than hard-coding the defaults below.

Default Value
Upload size 20 MiB per image
Decoded image 40 million pixels; 20,000 px per dimension
Generated outputs 16 files; 100 MiB total per image
Processing timeout 120 seconds
Built-in web profile 480, 960, 1440, 1920 px widths plus source width; WebP and AVIF; an optimized source-format copy

No upscaling. Widths larger than the source are skipped. Profiles are snapshotted when the job is accepted. A OnePlus length-prefixed metadata trailer is accepted for JPEG; arbitrary trailing data and multi-picture JPEG are rejected. Animation, 16-bit/HDR PNG, SVG, GIF, remote URLs, PDF, and video are unsupported.

Errors with a way forward.

API errors use the same envelope:

{ "error": { "code": "invalid_image", "message": "…" } }
HTTP Meaning Next step
400 Invalid multipart, field, profile, pagination, or ID Correct the request.
401 / 403 Authentication / browser CSRF failure Check the bearer key or sign in again; browser mutations need a matching Origin and CSRF token.
404 Missing or deleted resource Refresh the manifest; the file may have been deleted.
409 Idempotency conflict or incomplete ZIP selection Use the original submission parameters or wait for completion.
413 Upload or archive exceeds a byte/count limit Reduce the file size or archive selection.
422 Invalid image, unsupported structure/color/precision, dimension limit, or excessive planned outputs Read the message; re-export a static 8-bit sRGB image, resize it, or select a smaller profile.
429 / 503 Login rate limit, busy validation slots, or temporary service failure Back off and retry. Keep the same upload key after an ambiguous failure.

Do not blindly retry a permanent validation error with the same file. If a browser request is interrupted after upload, the server may already have accepted it; retry the same file/profile with the original idempotency key.

Know what stays.

GET/health/live

Unauthenticated process liveness.

GET/health/ready

Unauthenticated readiness: database and writable storage access plus the startup encoder probe result.

Images are processed on your instance and retained until explicitly deleted. There is no automatic expiry. Use HTTPS, keep keys server-side, back up database and image storage together, and monitor worker health.

Need only the API? Set UI_ENABLED=false. Bearer endpoints keep working. Public multiuser deployments require additional isolation, quotas, rate limits, and retention controls.
